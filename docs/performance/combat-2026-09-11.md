# Crowded combat performance — 2026-09-11

Status: AMBER. Enemy rendering is cheaper; physical low-end devices and sustained remote multiplayer combat remain validation gaps.

## Change

Zombie and skeleton constructors now combine rigid sibling geometry sharing a material. Animated heads, arms and legs retain their pivots, materials and transforms. Terrain, attack warnings and combat timing are unchanged by this patch. The geometry test compares every triangle vertex before and after batching, including an animated pivot rotation.

## Client measurement

Local headless Chromium, 800 × 600, 24 replicated enemy visuals (16 zombies, 8 skeletons), periodic warnings and particle bursts. Each CPU setting samples 12 seconds after terrain loading and warmup. These are single-run comparisons, not statistical guarantees or physical-device measurements. Browser CPU throttling does not emulate a weaker GPU.

| Metric | Before | After |
| --- | ---: | ---: |
| Peak draw calls, native CPU | 1,770 | 1,219 |
| Native CPU p95 frame interval | 79.9 ms | 74.0 ms |
| Native CPU p95 render submission | 13.9 ms | 10.3 ms |
| 4× CPU throttle p95 frame interval | 224.5 ms | 80.3 ms |
| 4× CPU throttle p95 render submission | 105.9 ms | 39.3 ms |

Peak native draw calls fell 31%. The post-change run passes the provisional 100 ms stall threshold at both settings. This is not a 30/60 FPS acceptance target: p95 frame intervals still exceed 33.3 ms. Effects are emitted every 12 sampled frames, so faster runs also generate effects more frequently. Internal frame diagnostics measure CPU execution; the benchmark separately measures requestAnimationFrame intervals. Render submission timing does not measure total GPU execution.

The benchmark deliberately disconnects networking before inserting enemy visuals. It measures client crowd rendering, not 24 rendered remote players or complete multiplayer combat. Server load is measured separately below. Live Vercel/Colyseus deployment was not exercised by this run.

Run explicitly on a quiet machine in PowerShell:

```powershell
$env:COMBAT_PERF='1'
npx playwright test e2e/combat-performance.spec.js --retries=0 --reporter=line
```

The usual E2E setup starts an isolated local server. The recorded run used the same Playwright configuration with an already-running isolated E2E server on port 2649. COMBAT_MAX_FRAME_P95_MS overrides the default 100 ms threshold; retain the reported raw timings when comparing machines. Ordinary E2E runs skip this hardware-sensitive benchmark.

## Server load

24 SDK clients across three dungeons, eight clients per dungeon, separated parties, 60.8 seconds:

- 22,524 messages, 370 messages/second.
- Event-loop delay: mean 29.02 ms, p99 38.96 ms, max 56.43 ms.
- Heap growth: 1.61 MB.
- 530 rejected requests; the harness sends requests from basic profiles, including unavailable abilities. This is mixed traffic, not proof of sustained successful ability combat.
- Load assertions passed, including positioned-effect fanout skips for distant clients.

Server and SDK clients share a Node process in this harness; delay and heap numbers include both. Unit checks overlapped part of the run, so this is not an isolated server capacity measurement. The first run omitted BLOCKCRAFT_METRICS and failed the effect-filter assertion because metrics were unavailable; the recorded rerun enabled it.

```powershell
$env:BLOCKCRAFT_METRICS='1'
$env:DUNGEON_LOAD_DURATION_MS='60000'
$env:DUNGEON_LOAD_SPREAD='1'
$env:DUNGEON_LOAD_REQUIRE_FX_SKIPS='1'
node tools/dungeon-load-test.js
```

## Verification and next validation

Lint, formatting, static build and all 882 unit tests passed. The crowded browser benchmark passed at both CPU settings before adding its explicit opt-in switch.

Next: repeat on physical integrated-GPU hardware with a 33.3 ms p95 target, then run equipped players through sustained boss fights against a remote server. Record frame intervals, server tick delay, RTT, rejection reasons, disconnects and memory over at least 15 minutes. Keep enemy silhouettes and warning visibility in the visual acceptance criteria.
